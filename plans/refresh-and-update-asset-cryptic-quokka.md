## Part 3 — What's left in the clip engine (audit)

Genuinely still open, most-consequential first. **None of these are regressions from the fix**
— items 1–3 are pre-existing gaps the fix exposed.

1. **Generation failures return HTTP 200.**
   [suggest/route.ts:121](app/api/media/[id]/suggest/route.ts#L121) explicitly returns
   `{ ok: false }, { status: 200 }`. This is the direct reason a fully-deterministic failure
   sat broken for two weeks until Paul spoke up — nothing HTTP-level could see it. Needs a
   real signal (non-2xx, or a Slack alert via the existing [lib/notify/slack.ts](lib/notify/slack.ts)).
   Deferred in the original plan; still the highest-value fix here.
2. **The grammar-cap fallback is `console.warn`-only, and I could not verify it.**
   [generate.ts](lib/clipping/generate.ts) warns and retries unconstrained if the schema is
   still over the cap. `kessel runtime-logs` returns nothing when piped in a non-interactive
   shell (a control search for `GET` was also empty), so **whether the shrink was sufficient
   is still unconfirmed.** The 07:46 run succeeded either way, but we can't tell *which path*
   carried it. Persist the signal somewhere durable (a flag on the Media Source row, or a
   counter) instead of stdout — otherwise the escalation trigger in the original plan
   (split `generateStrategy` into two parallel structured calls) can never fire.
3. **`Virality Gates` came back degenerate.** All 7 clips from the 07:46 run got the identical
   pair `[Controversy, Uncommon Knowledge]` — including "Everyone Listening Has A Guardian
   Angel" and "Homeless To VP". [prompt.ts:31](lib/clipping/prompt.ts#L31) tells the model
   "Never empty; a clip that hits none does not qualify", which pressures it to always fill
   both. Since `e1da2c6` switched ranking to fight-likelihood, a non-discriminating gate
   signal weakens the ranking it feeds. Prompt-quality fix, not a code bug.
4. **`CLIPS_SYNC` outcome fields are not enabled in the Airtable sync field set.**
   [field-map.ts:549-566](lib/airtable/field-map.ts#L549-L566) records this. Consequences:
   `clip-learn.yml` runs **every Monday against empty data**, and the `App Clip ID`-based
   ticket-link reconcile in [lib/media/ticket-links.ts](lib/media/ticket-links.ts) is a silent
   no-op. One Airtable click; highest ROI per effort of anything in this list.
5. **12 untracked macOS `* 2.ts` / `* 2.tsx` duplicates** are still in the tree and still
   type-checked by `tsc` (`lib/clipping/clip-brief 2.ts`, `lib/cover/clip-cover 2.ts`,
   `app/cover-generator/* 2.*`, `components/ui/{Slider,Toggle} 2.tsx`, …). Byte-identical,
   imported nowhere. Deferred twice now.
